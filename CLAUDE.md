# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Vanilla JS Tetris (HTML5 Canvas). No `package.json`, no build, no linter, no tests. README and UI text are in Spanish.

## Run

Open `index.html` directly, or serve statically: `python -m http.server 8000` then `http://localhost:8000`.

## Architecture

Three files: `index.html` (DOM + two canvases), `style.css`, `game.js` (all logic, single script, global scope, `'use strict'`).

- `index.html` hardcodes canvas size: `#board` is 300×600 and `#next-canvas` is 120×120. These must equal `COLS*BLOCK` × `ROWS*BLOCK` in `game.js`. Changing `COLS`/`ROWS`/`BLOCK` requires editing the HTML too.
- Game state lives in module-level `let` variables declared on one line (`board`, `current`, `next`, ...). `init()` resets all of them; the restart button calls `init`.
- Board cells: `0` empty, `1–11` piece type (8 = tuerca, 3×3 ring with empty center; 9 = Y pentomino in a 4×4 box; 10 = U pentomino in a 3×3 box; 11 = + cross pentomino in a 3×3 box; `randomPiece` draws from `PIECE_WEIGHTS`, classics 6 vs 1 for types 8–11; 12 = single 1×1, reward only: `clearLines` sets `rewardPending` on a 4-line clear and the next `spawn()` makes it `current` while keeping `next`; 13 = bomb 1×1, reward every `BOMB_EVERY` lines: `clearLines` sets `bombPending` when `lines` crosses a multiple, the next normal `spawn()` makes the new `next` a bomb, and `lockPiece` calls `explode()` (clears 3×3, no gravity, not merged) instead of `merge()`; 14/15 = rayo 1×1 horizontal/vertical, every `LIGHTNING_EVERY` lines: `clearLines` sets `lightningPending`, `spawn()` makes `next` a rayo only if no bomb is pending (bomb wins), rotate toggles 14↔15, `lockPiece` calls `strike()` — horizontal removes its row with gravity, vertical empties its column; no score/lines, not merged; 16 = tinte 1×1, every `TINT_EVERY` lines: `tintPending`, lowest priority after bomb and rayo, `lockPiece` calls `tint()` — turns every board cell of the color directly below it into 17 = comodín (rainbow, board-only, no `PIECES` entry; +`WILD_BONUS`×level per comodín cell in a cleared line); no-op if below is empty/floor/comodín; 18 = gravedad 1×1, every `GRAVITY_EVERY` lines: `gravityPending`, lowest priority after bomb, rayo and tinte, `lockPiece` calls `gravity()` — each column drops its cells to the floor (no gaps), not merged, then `clearLines()` scores any rows completed; 19 = congelar 1×1, every `FREEZE_EVERY` lines: `freezePending`, lowest priority after gravedad, `lockPiece` sets `freezeLeft = FREEZE_MS` — `loop` counts it down by `dt` instead of accumulating `dropAccum` (auto-fall stops, player input still works), `draw()` overlays the countdown; not merged, no score; 20 = basura, board-only, no `PIECES` entry, only created by `addGarbage()` in the `survive` challenge). The same number indexes `COLORS` and `PIECES`, so a locked cell keeps its color.
- Combo: `combo` counts consecutive locks that cleared lines. `clearLines()` returns `cleared`, increments `combo` and multiplies line + wild score by it (not soft/hard drop). `lockPiece` resets `combo = 0` only when a normal piece clears nothing; powerups (bomb, rayo, tinte, congelar) are neutral; gravedad counts only if its `clearLines()` clears rows. HUD `#combo` shows `xN` when `combo > 1`, `draw()` overlays `COMBO xN`.
- T-spin: `lastRotate` is true after a successful `tryRotate` and cleared by any successful move/fall and by `spawn()`. `lockPiece` calls `isTSpin()` (type 3, `lastRotate`, ≥3 of the 4 corners of the 3×3 box filled or out of bounds) before `merge()` and passes it to `clearLines(tspin)`, which scores `TSPIN_SCORES[cleared]` (400/800/1200/1600) instead of `LINE_SCORES`, still × level × combo. A T-spin with 0 lines scores `TSPIN_SCORES[0]*level` but still resets `combo`. `tspinText`/`tspinLeft` drive a `draw()` banner (`TSPIN_FLASH_MS`), counted down in `loop`.
- B2B: `b2b` counts consecutive "hard" clears (4 lines or T-spin with ≥1 line), set in `clearLines()`. A hard clear with `b2b > 0` before it multiplies only the line base (`base*level`, not wild bonus) by `B2B_MULT` (1.5), then × combo. A normal 1–3 line clear resets `b2b = 0`; no-clear locks, 0-line T-spin and powerups leave it untouched. HUD `#b2b` shows `xN` when `b2b > 1`, `draw()` overlays `B2B xN` stacked under freeze/combo.
- Perfect Clear: in `clearLines()`, after a clear that leaves `board` fully empty, adds `PERFECT_BONUS`×level (flat, no combo/B2B multiplier) and sets `perfectLeft` (`PERFECT_FLASH_MS`) for a `draw()` banner, counted down in `loop`. Gravedad can trigger it via its `clearLines()`.
- Desafío: `CHALLENGES` (goal `lines`|`score`|`tetris`, `target`, `timeMs`); `#mode-select` (`-1` = normal) is read by `init()` into `challenge`, `timeLeft`, `tetrises` (incremented in `clearLines` on 4 lines). `lockPiece` checks `challengeProgress()` ≥ target before `spawn()` → `winChallenge()` → `endGame('¡DESAFÍO SUPERADO!')`. `loop` counts `timeLeft` down always (congelar doesn't stop it; pause does) → `endGame('TIEMPO AGOTADO')`. Unlocked index persisted in `localStorage` (`tetris-challenges`); `buildModeOptions()` disables locked options. `#challenge-info` (`hidden` attr) shows `#goal`/`#timer` via `updateHUD`/`updateTimer`. Powerups stay active. `survive` goal (`garbageMs`, `garbageLeft`): progress = seconds elapsed, reaching `timeLeft <= 0` calls `winChallenge()` instead of `TIEMPO AGOTADO`; `loop` counts `garbageLeft` down with the clock (congelar doesn't stop it) and calls `addGarbage()` every `garbageMs` — shifts the board up, pushes a type-20 row with one random hole, lifts `current` one row if it collides, `endGame()` if the top row is occupied or `current` can't fit. `draw()` shows a red bar (top, 4px) filling toward the next row.
- Desafío `clear` (bloques fijos): `CHALLENGES` entries with `layout` (array of `COLS`-char strings, `#` = fixed block, bottom-aligned). `init()` calls `placeLayout()` → board cells of type 21 (`FIXED_TYPE`, board-only, no `PIECES` entry) and stores the count in `fixedTotal`. Progress = `fixedTotal - countFixed()`; target comes from `challengeTarget()` (`fixedTotal` for `clear`, `ch.target` otherwise). Fixed cells clear like normal cells (lines, bomb, rayo, gravedad); `tint()` ignores them. `lockPiece` calls `updateHUD()` in challenge mode before the win check so bomb/rayo clears refresh `#goal`.
- Chain FX: `clearLines()` records the full rows (`fullRows`, original y + colors) and, after scoring, calls `chainFx(rows, gained, cleared, strong)` → `flashRows/flashLeft` (white flash), `particles` (more per cell with higher `combo`), `floats` (`+points`), `comboPulse` (canvas font size) and `pulseEl()` on `#combo`/`#b2b` (CSS `.pulse`). State is updated in `loop` and reset in `init`. Audio is Web Audio synth (`getAudio` lazily creates the `AudioContext`, `playTone`, `playClear` pitch rises with combo, `playPerfect`, `playBreak` when combo >1 is lost, T-spin 0-line blip). `#sound-toggle` mutes via `setMuted()`, persisted in `localStorage` (`tetris-sound`), no keyboard shortcut.
- Piece lifecycle: `spawn()` (current = next, new next; calls `endGame()` if spawn collides) → move/rotate/drop → `lockPiece()` = `merge()` + `clearLines()` + `spawn()`.
- `clearLines()` owns score/lines/level/`dropInterval` updates; `hardDrop`/`softDrop` add their own score. HUD refreshes via `updateHUD()` (the keydown handler also calls it after every key).
- Game loop: `loop(ts)` via `requestAnimationFrame`, accumulates `dropAccum` against `dropInterval`. Pause/game over use `cancelAnimationFrame(animId)`; unpausing restarts `loop` manually. `animId` must be cancelled before starting a new loop (see `init`).
- Theming: colors are CSS variables in `style.css` (`:root` = dark, `[data-theme="light"]` = light). `setTheme()` in `game.js` sets `data-theme`, persists to `localStorage` (`tetris-theme`), caches canvas colors (`--grid`, `--block-edge`) and redraws `draw()`/`drawNext()` so paused/game-over states update. No keyboard shortcut for the theme; the toggle button blurs itself and swallows Space/Enter.
- Rotation: `rotateCW` (transpose + reverse) with horizontal kicks `[0,-1,1,-2,2]` in `tryRotate`; no SRS, no floor kicks.
